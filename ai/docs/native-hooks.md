# Praat API 流程的原生 Hooks 与守卫

依赖沿用 `pydantic-ai-slim[openai]==2.52.0`，通过 `Agent(capabilities=[Hooks(...)])` 接入；没有引入另一套代理框架。现代前端和旧 Tk API 前端共用 `cloud_agent.py` 的检查。本地 Qwen 规划器仍走原有执行路径。

| 要求 | 程序检查及处理 |
| --- | --- |
| 不编造对象，尊重编号和类型 | `before_tool_execute` 按快照精确匹配对象；固定工具模板核对类型。部分名称不用于猜对象；用户指定目标不能换成另一个已有对象。应用创建的对象须刷新确认后才可引用。 |
| 整段请求不偷偷沿用旧选区 | 应用设置整段范围标记，覆盖编辑器选区和默认点查询时刻。显式局部范围须有用户请求；音高走向的分段须先取得真实总时长。报告不能把分段均值说成整段均值。 |
| 不重复失败调用 | 以实际对象、范围和固定脚本识别相同调用；重复调用通过 `SkipToolExecution` 跳过。把默认参数显式写一遍不算修正。 |
| 复用成功测量 | 复用本轮或继续分析中保存的同目标、同范围成功证据，通过 `SkipToolExecution` 返回已有结果。 |
| `custom_script` 必须是 Praat | 执行前沿用脚本校验，补查常见 Python、JavaScript、shell 语法、对象引用和命名；缺省对象先绑定原目标。整段请求使用可核实范围的内置工具。自由脚本的语法最终由 Praat 执行器判定。 |
| 新名字来自用户 | `name` / `new_name` 以及脚本中的显式命名须匹配原请求或本次继续方向中的新名字。未提供名称时使用内置工具既有默认命名。 |
| 测量数字不伪造 | `after_output_process` 核对正文及覆盖说明中的数字、单位、量名、对象、范围和同一行的证据引用。音频定性观察、操作记录及未定义值不能充当测量。 |
| 推导说明输入和公式 | 引用真实证据量，以有限四则表达式生成输入、算式、结果和引用。程序检查单位维度，不执行模型提供的 Python 代码。 |
| 音调判断先有走向 | 明确的录音音调结论须引用同目标的有效分段基频、起终点或适用斜率。只有均值不通过；绝对斜率不能单独证明升降方向。 |
| 「没有音频输入」不能当结论 | 本轮已有测量证据，或对象列表里有可测量的声音对象时，正文出现「没有音频输入／无法测量」且没有引证，按 `report.input_claim_conflict` 阻断。报告指令与报告上下文不把「没有音频」写成可复述的句式。 |

报告上下文中的 `evidence_ids` 按证据顺序编号，`quantity_refs` 给出每个可用数值的行号及量名。例如，某证据的第三个数值为平均基频，则引用 `E1.q3`。实测陈述逐行引用 `[E1]`。上下文摘录后只向报告守卫提供模型本次实际收到的证据。

推导使用 `{{calc:E1.q1/E2.q1*100|%}}`，由程序替换为真实输入、算式和结果。一般知识须标注；下一步的建议参数不当作已经取得的测量。

阻断类调用或报告通过 `ModelRetry` 进入有限纠正流程；缺少可匹配引证、无效证据编号、无法核对的推导和覆盖项格式由守卫补齐、移除或标注。工具执行次数、请求次数和失败分支继续使用现有预算。报告纠正不会重跑已完成的对象操作；纠正失败时保留草稿并遮蔽无法核对的数值，附核对原因，该说明面向用户而不含给模型的指令句；没有草稿时使用阶段记录。执行前被拒的提案不记为实际测量失败。守卫阻断与自动修正按规则 ID 计入 `state.metrics.guard_blocks` / `guard_repairs`。

这些守卫检查可识别的数值、引用、明确音调结论和工具参数，不能证明所有自然语言解释正确。尤其是有音高走向只是音调判断的必要证据，还需要结合音节对齐和参照材料。

回归测试：`test_tool_guards.py` 验证真实 SDK 的拦截、跳过、复用、刷新和报告纠正；`test_report_guards.py` 验证证据匹配、单位、公式与音调条件。
