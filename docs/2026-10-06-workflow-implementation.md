工具结果现在独立保存和展示；可证明完成的单项测量直接结束，解释按工作流程策略启动。报告失败、阶段超时和用户取消不会删除已经发布的结果。实现沿用 Python、固定 SDK、现有 pydantic-graph、React、Praat dispatcher、Pi 原生历史、缓存适配和 guard，没有新增模型分类请求或工作流框架。

## 行为与配置

- `workflow_policy.py` 定义宿主校验的冻结策略、有限的测量契约、完成判定和现有事实的结果投影。`modern.workflow` 持久化；设置 RPC 单独返回 workflow。缺字段补默认，枚举、布尔和整数严格校验；不匹配预设的组合归为自定义。旧配置读取不落盘。
- 预设为快捷结果、自动平衡、深度分析、纯聊天及自定义。默认自动平衡：L0 开，L1 每问题一次，L2 按需／简短，L3 手动，L4 开。L2 默认 15 秒／1 个实际请求；深度分析 60 秒／2 个实际请求。
- 任务启动时复制有效配置并保留完整策略快照。执行、工具 guard、继续动作和音频恢复服从快照；实际材料、能力、取消、投递事实和总预算仍优先。关闭 L0 同时禁止快路、模型工具执行和 Praat 音频导出。L4 关闭时普通聊天也不会请求模型。
- L2 使用单调时钟，从准备到校验和宿主保存共用截止时间；HTTP timeout 取原超时与剩余阶段时间的较小值。阶段压缩、传输重试、输出上限纠正和报告修正共用阶段请求上限及原任务总账。上限耗尽后不自动启动另一长流程绕开限制。
- 思考档位只作用于实际模型请求。默认确定性快路不受强制深度思考开关影响；Token 模式不再决定现代云端流程的阶梯启用状态。旧 Tk、本地模型仍沿用原路径。

## 测量、结果与继续

当前快路限定明确的当前／选中声音单项请求，不泛化诊断、VOT 边界、复合操作或未知参数：

| 请求 | 现有工具 | 单位与参数语义 |
| --- | --- | --- |
| 总时长 | `duration` | 秒；整个时间对象 |
| 平均基频／基频统计／平均 F0 | `pitch_statistics` | Hz；继承原模板的范围、75–600 Hz 默认分析参数及防倍频统计修复 |
| 平均强度／强度统计 | `intensity_statistics` | dB；继承原模板的范围及能量平均算法 |

快路经相同 schema／对象／范围 guard 归一，再进入原 dispatcher 和工具模板。已有选区继续按原范围策略处理。没有有效数值的统计，例如无周期声源的平均基频，保留工具结果及投递事实，但不增加成功测量证据，不标记目标完成。

规划后的提前结束仅适用于应用能证明的闭合单项契约：检查原交付项、量名、原对象身份、绑定范围、成功执行、有效数值及投递状态；检查当前调用集合，混合调用或未完成任务不能提前结束。提前退出前保存 SDK 生成的待发送 ToolReturn 请求，保留已执行调用的真实配对，不发完成宣布请求，也不创建空 L2 上下文。

结果投影包含原始工具行、可提取的量／值／单位、对象、范围、证据引用、执行状态及结果有效性。宿主先更新同一任务的 evidence 记录和消息，再发布结果事件；正式解释独立更新，未验证草稿仅作诊断保存。没有可用后续阶段时由本地模板交代缺口。

“解释结果”“分析原材料”“通用讨论”是新的可见用户轮次。宿主绑定来源任务、原目标、原对象与已有证据，恢复来源策略快照，不重新测量或修改全局预设。原材料动作还核对原文件 SHA-256、原片段来源和实际音频能力；源文件改变、丢失或能力不可用时收起入口并拒绝执行。临时 Praat 快照仍在任务关闭时清理，不用后来变化的对象冒充原录音。

## 缓存、历史与预算验证

工作流程判断留在应用层。解释详略只加入报告末尾任务数据，不改变前导 system、工具排列或输出 schema。L1 控制执行问题的有限纠正，不改 SDK 工具协议；跳过 L2 不产生报告历史。

离线 SDK 与本机 HTTP 测试验证了三次报告追加及必要 guard 修正的最终请求：前一请求的 HTTP messages 是下一请求的精确前缀，静态 schema／规则保持稳定。仍沿用原缓存 usage 归一化和去重，缺报计数为 null，没有预热或保活请求。

本次没有真实供应商 A/B，因此不声明真实云端命中率、输入成本改善幅度或固定延迟收益。已验证的是请求数：明确快路零请求；闭合的规划测量一次规划请求后结束；L2 修正实际请求受 1／2 次设置及任务预算约束。
