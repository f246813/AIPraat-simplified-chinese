# 不透明度滑杆交互

状态：已实现。本文描述外观面板中不透明度滑杆的当前交互、实现位置与验收入口。现有界面与功能见[外观面板 UI](APPEARANCE-PANEL-UI-DESIGN.zh-CN.md)。

## 交互结论

不透明度采用按位置连续调整的水平滑杆，输出为 20%–100% 的整数百分比。鼠标拖动和点击轨道不吸附到整十值；1% 是数值精度，10% 只作为 PageUp／PageDown 的键盘大步长。

保留当前 328 × 248 的面板、横向色卡、当前百分比、圆形手柄与中性灰轨道。手柄标称直径 18、控件行高 32 个逻辑像素；不增加分段刻度、端点文字、输入框或精细调整模式。手柄清晰描边、抗锯齿圆弧和完整重绘方式继续保留。

## 实现位置与当前行为

实际入口是编辑器“外观”面板中的 `TRACKBAR_CLASS`，由 [EditorAppearancePanel.cpp](../foned/EditorAppearancePanel.cpp) 创建、绘制并子类化；回调经过 [FunctionEditor.cpp](../foned/FunctionEditor.cpp) 更新窗口不透明度，再调用 [motifEmulator.cpp](../sys/motifEmulator.cpp) 的窗口合成接口。

| 检查项 | 当前行为 |
| --- | --- |
| 数值精度 | 控件范围 20–100、`TBS_NOTICKS`、方向键步长 1、`TBM_SETPAGESIZE` 为 10；鼠标路径由 `sliderPercentForPointerX` 把指针位置映射到最近整数百分比，不沿整十取整 |
| 手柄命中 | `sliderGeometry` 同时给绘制、抓取命中和鼠标映射提供圆心、半径、描边与抓取区；按下先判抓取区，命中即记录相对圆心的水平偏移，按下本身不改值 |
| 轨道按下 | 抓取区之外按轨道处理，直接采用该位置对应的百分比，并继续作为同一次拖动跟踪，不进入分页计时 |
| 按住与跟踪 | 面板自己 `SetCapture`，用有符号客户区坐标计算位置；纵向距离和面板外坐标不改变规则，水平超出行程时限制在 20%／100% |
| 提交次数 | `previewOpacity` 只在数值有效变化时调用，一次操作结束时调用一次 `commitOpacity`；原生结束通知不再重复业务提交 |
| 结束与取消 | `WM_CAPTURECHANGED`、`WM_CANCELMODE`、Esc、面板隐藏与销毁共用结束入口，退出标记先于回调与释放捕获更新，保留最后成功值且不重新抢占捕获 |
| 系统拒绝 | 回写恢复最后实际生效值并终结该次拖动，沿用现有具体错误反馈，不在每个移动事件重复报错 |
| 100% 边界 | 100% 与较低值之间切换 `WS_EX_LAYERED` 并重绘所属窗口，其余百分比只更新 alpha；该切换由验收单独计时记录 |
| 端点行程 | 布局创建或 DPI 重建时，`measureSliderTravel` 在控件尚未显示的同进程初始化里读取两端圆心并恢复当前值；拖动过程中不再改到端点探测 |

## 交互

| 输入 | 行为 |
| --- | --- |
| 按下手柄及其抓取区 | 不改变数值，记录按下点相对手柄圆心的水平偏移，立即进入拖动 |
| 拖动手柄 | 保留抓取偏移，按水平位置映射到最近的 1%；跨过 29／30／31、59／60／61 等位置时无特殊阻力或跳转 |
| 点击轨道空白位置 | 直接定位到点击位置对应的整数百分比；继续按住移动时自然接续拖动，不启动分页计时 |
| 拖出轨道或面板 | 左键仍按住且捕获有效时继续跟踪，纵向距离不触发回退；水平超出行程时限制在 20%／100% |
| 松开鼠标 | 采用松手时的最终水平位置，结束拖动并提交一次；之后移动鼠标不再改变数值 |
| 方向键 | 保留原生方向约定和每次 1% 的调整，不向整十取整 |
| PageUp／PageDown | 分别减少／增加 10 个百分点，例如 64%→54%／74%，并限制在范围内 |
| Home／End | 分别到 20%／100% |
| Esc、外部点击、切换应用 | 结束当前拖动，保留最后成功应用的数值，按现有规则关闭面板 |
| 捕获被系统或其他窗口取走 | 结束拖动、清除按住状态，保留最后成功值；不重新抢占捕获 |

手柄抓取区采用至少 24 × 32 个逻辑像素的矩形，且不小于可见圆形加描边，整体不超出滑杆控件。圆心靠近控件边缘时，抓取区向仍有空间的一侧扩展，不因贴边而被裁小；可见圆形的任何一点都不会被读成轨道按下。先判断抓取区，再判断轨道区域。32 像素行高与原有间距足够，不扩大面板或覆盖百分比、色卡。

范围内保持单调映射。静止鼠标不重复产生值变化；快速移动允许一次跨越多个百分点，不能用“每条鼠标消息最多变化 1%”造成追赶和延迟。仅在数值变化时更新合成；同值事件不反复重绘或提交。

### 统一几何与数值映射

绘制、抓取命中和鼠标映射共用一组几何数据：端点圆心 `xMin`／`xMax`、当前实际圆心、半径、描边宽度、抓取区和有效行程。均以当前控件客户区的设备像素计算，DPI 缩放只应用一次。

```text
L = xMax - xMin
grabOffset = pointerDownX - drawnThumbCenterX   // 抓住手柄时
grabOffset = 0                                // 点击轨道时
x = clamp(pointerX - grabOffset, xMin, xMax)
value = clamp(round(20 + 80 * (x - xMin) / L), 20, 100)
```

端点取当前原生控件的实际手柄中心行程，不能直接把控件宽度或轨道外框宽度当作行程。布局创建或 DPI 重建时，在控件尚未显示的同进程初始化中读取两端位置并恢复当前值；拖动过程中不反复改到端点探测。圆心的半像素对齐也属于这份几何数据。

应用整数值后，由原生位置读回绘制圆心。量化与设备像素对齐产生的距离应有界：范围内 `|实际圆心 + grabOffset - 指针 x| ≤ L/160 + 1` 个物理像素。该上限包含半个 1% 步长和像素舍入，不允许额外的整十吸附距离；超出端点后按边界限制判断。

### 拖动生命周期

只有“空闲”和“拖动中”两个状态，另有抓取偏移、最后成功值和本次是否发生变化的记录。

1. 左键按下先设置焦点，按统一几何判定手柄或轨道；成功取得捕获后进入拖动，再应用轨道点击的定位值。获取捕获失败时保持原值；按下事件只由一条路径处理。
2. 捕获期间使用有符号客户区坐标计算位置，正确处理面板外的负坐标。`WM_MOUSELEAVE` 只清除悬停，不结束拖动；不根据纵向距离恢复初始值。
3. 正常松手先计算最后位置，再退出拖动状态、按需提交，最后释放自己持有的捕获。无值变化的抓取不产生业务提交。
4. `WM_CAPTURECHANGED`、`WM_CANCELMODE`、Esc、面板隐藏和销毁共用结束入口。退出标记先于回调和释放捕获更新，避免释放后收到的捕获通知再次提交。
5. 捕获异常丢失时保留最后成功值，不按丢失后的鼠标位置补算。窗口隐藏或销毁后不再接受该次拖动的消息。

[SetCapture](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setcapture) 用于保证按住后离开控件仍能接收鼠标；[WM_CAPTURECHANGED](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-capturechanged) 也会由主动释放触发，微软明确要求收到该消息时不要重新设置捕获。

## 实现边界

保留 `TRACKBAR_CLASS` HWND、键盘、Tab 焦点及原生辅助功能数值接口。在现有子类过程中接管这条鼠标交互链：按下、移动、松手、取消和捕获变化；消费已接管的事件，避免原生分页或拖动再执行一次。不另造窗口控件或引入 UI 框架。

| 位置 | 职责 |
| --- | --- |
| `foned/EditorAppearancePanel.cpp` | 共享几何、抓取优先级、鼠标状态、坐标映射、捕获清理、一次提交；保留完整重绘与现有圆环像素覆盖 |
| `foned/EditorAppearancePanel.h` | 说明 preview／commit 的调用语义；沿用现有回调形式 |
| `foned/FunctionEditor.cpp` | 窗口独立状态与实际应用值；失败回写与拖动结束相容 |
| `sys/motifEmulator.cpp` | alpha 合成路径；100% 处切换 `WS_EX_LAYERED`，其余百分比只改 alpha |
| `ai/tests/native_appearance_panel.cpp` | 同进程检查几何、指针距离、边缘按下、取消与提交次数，并复用已有绘制验收 |
| `tools/verify-native-appearance.ps1` | `opacity` 与 `drag` 阶段用真实鼠标与键盘输入验证实际编辑器中的连续性、捕获、失焦、百分比与 alpha 一致性，并记录拖动轨迹 |

所有输入汇入同一个值更新入口。`previewOpacity` 只处理拖动中的有效变化，最终操作完成后调用一次 `commitOpacity`；键盘重复按下可持续调整，原生结束通知不再重复业务提交。回调成功后同步可读名称与数值，避免拖动中辅助功能仍保留旧百分比。

系统拒绝设置不透明度时，使用已有状态回写恢复最后实际生效值，并终结该次拖动；不让显示值继续追随未生效的请求。沿用现有具体错误反馈，避免每个移动事件重复报错。普通拖动不重建声谱图、音高、共振峰或脉冲分析缓存。

## 验收要求

验收分两层。`ai/tests/native_appearance_panel.cpp`（由 `tools/verify-native-appearance-layout.ps1` 编译运行）在同一进程记录按下点、命中类型、原生手柄矩形、绘制圆心、指针坐标、控件值、通知类型和提交次数；其消息泵忽略系统排队的鼠标移动，只采用测试指定的同步坐标，避免捕获期间混入物理指针的位置。`tools/verify-native-appearance.ps1` 的 `opacity` 与 `drag` 阶段用真实鼠标与键盘输入操作正在运行的编辑器，记录指针坐标、控件值、实际 alpha、捕获窗口与提交结果。只发合成窗口消息的测试可验证状态与绘制，不能替代实际输入和捕获链路。

真实输入这一层不发送带指针的原生查询：`TBM_GETTHUMBRECT`、`TBM_GETCHANNELRECT` 之类的消息不做跨进程转编组，跨进程发送会让控件往调用方地址写入，直接使编辑器崩溃，因而不可用。手柄位置改由两个可信来源取得——控件对每个指针位置自己报告的百分比（拟合出一条直线，端点即实际手柄行程），以及在窗口完全不透明时从桌面像素读回的可见圆形；两者对不上就是缺陷。

| 场景 | 通过条件 |
| --- | --- |
| 整十附近慢拖 | 在 30／40／50／60／70／80／90% 两侧按物理像素缓慢往返，可停到相邻非整十值；距离满足量化上限，无额外停滞或跳跃 |
| 从非整十值开始 | 从 37%、64%、87% 起拖，不出现固定 10% 的追赶；Page 键仍明确按相对 10 个百分点移动 |
| 手柄中心、圆周与抓取区 | 中心、上下左右及四个斜向圆边分别按下，按下本身不跳值；任一抓取位置继续移动时保持原始水平偏移 |
| 轨道点击与按住 | 左右任意位置直接定位，继续按住可拖动；静止按住不按计时器重复分页 |
| 离轨与面板外松手 | 上下离轨、移出面板、跨到另一窗口区域后继续按住仍跟踪；外部松手能结束，随后鼠标移动不再改变值 |
| 快速往返与端点 | 快速扫过整条轨道，不积累滞后；20%／100% 可达，超界保持边界，返回行程后按位置恢复，无残影 |
| 取消与重入 | Esc、Alt+Tab、捕获转移、隐藏及销毁后无悬挂拖动；主动释放捕获不重复提交；重新打开可立即抓取 |
| 键盘与辅助功能 | Tab、方向键、Page 键、Home、End 正常；范围、当前值、名称和实际生效值一致，焦点与选中态仍可区分 |
| 合成反馈 | 百分比、填充、手柄和实际 alpha 一致；静止不重复回调，单次鼠标操作最多一次最终提交；99%↔100% 的样式切换单独记录 |
| 视觉与缩放 | 100%／125%／150%／200% 检查边缘抓取、偏移和绘制；圆角、手柄极值描边、色卡间距无退化。跨 DPI 重新打开后几何重新计算 |

事件记录要能区分数值量化、分页、捕获丢失和合成耗时；不能只用最终数值在范围内或一张截图作为通过依据。逻辑 DPI 绘制检查与实际系统缩放、跨显示器输入验收分别记录。

验收证据放入 `test-records/`，包含拖动轨迹、事件序列和必要截图／录屏。设计文档不记录一次性测试通过数，当前未实施的目标不写成已支持能力。

同进程一层的结果在 `test-records/appearance-panel-native/`：`layout.json` 按逻辑 DPI 记录尺寸、端点行程与量化上限，`drag-events.json` 记录每次按下点、命中类型、原生手柄矩形、绘制圆心、控件值、通知类型与提交次数；`panel-*.png` 是各缩放下的面板内容，`frame-*.png` 是圆角边缘层，`drag-*.png` 是拖动中的滑杆控件行。真实输入一层的结果在运行时指定的 `-Stage` 目录：`checks.json` 按场景记录判定条件与当时的实测值，包括抓取偏移的逐次保持、按下网格、轨道定位、键盘逐键反馈与端点限制；`drag-input.json` 记录指针位置拟合出的映射与残差、从像素读回的圆形、整条轨道的拖动轨迹、捕获窗口检查点和 99%↔100% 计时。按实际启用的阶段生成画面、剪贴板输出和分析查询结果；`verification.json` 记录本次执行文件的哈希、检查项与结论。
