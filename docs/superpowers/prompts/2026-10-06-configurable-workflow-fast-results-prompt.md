# 实现交接 prompt

在当前 AIPraat 项目实施 `docs/superpowers/specs/2026-10-06-configurable-workflow-fast-results-design.md`，并遵循项目 `aipraat-prompt-cache` skill。先核实现有源码及已完成修复，再形成简短实施计划并完成改动。

目标：测量结果通过现有必要校验后立即交付，取消工具执行后强制 L2；解释按目标与用户策略启动。确定性单项测量零模型调用；需要规划的测量在交付项已证明完成后直接结束，不增加宣布完成的请求。不要增加分类模型，也不要用一条证据判定复杂目标完成。

设置新增“工作流程”：快捷结果、自动平衡（默认）、深度分析、纯聊天及自定义。支持 L0 开关；L1 关闭／每问题一次；L2 关闭／按需／始终、简短／完整、阶段时间与请求上限；L3 关闭／手动／自动；L4 开关。配置由宿主校验保存，任务启动时快照；所有入口与恢复路由共用策略。明确单次动作可覆盖阶段偏好，不能覆盖真实能力或执行条件。

先保存和展示结果，再解释；模型失败、超时或取消后结果仍保留，缺失解释标记部分完成。L2 初值按设计使用 15 秒／1 次，深度分析 60 秒／2 次；重试、修正和续写共享剩余阶段时间及任务总预算。Token 配置只管理预算，不隐式打开阶段。继续解释复用原证据与材料，不重复测量。

保留 Python／固定 Pydantic AI、React、Praat guard、原对象／范围、投递 unknown、失败／停滞计数、取消、知识／音频权限，以及现有 Pi 原生历史、稳定请求前缀、会话 runtime 和文件名线索规则。复用现有代码与事件；借鉴设计中的 Zoo Code 面板、OpenCode 配置和 LangChain 直接结束条件，不引入新的工作流框架。

当前目录非 Git 仓库，修改前备份受影响源码。完成相关行为／协议回归、前端构建与页面验证，报告改动、实际请求数及限制；本次实施不自动发付费云端请求或上传录音。
